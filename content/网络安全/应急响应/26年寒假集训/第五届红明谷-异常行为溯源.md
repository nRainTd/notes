# 概述

> [!info]
> 某企业网络安全部门人员正在对企业网络资产受到的攻击行为进行溯源分析，该工作人员发现攻击者删除了一段时间内的访问日志数据，但是攻击者曾传输过已被删除的访问日志数据并且被流量监控设备捕获，工作人员对流量数据进行了初步过滤并提取出了相应数据包。已知该攻击者在开始时曾尝试低密度的攻击，发现未被相关安全人员及时发现后进行了连续多日的攻击，请协助企业排查并定位攻击者 IP，flag 格式为：flag{md5(IP)}

提取信息：
1. 日志被攻击者删了，但是攻击者传输过的日志的流量被流量监控设备捕获了；
2. 工作人员初步过滤了流量，提取出了一个流量包；
3. 攻击者先是低密度攻击，后来进行了连续多日的攻击；
4. 要求定位攻击者 `IP`。

## 3 `.pcap` 流量包的文件结构

`.pcap` 流量包的文件结构非常简单，仅由一个头部和一系列帧组成：

![[第五届红明谷-异常行为溯源-260208-172327.png]]

### 3.1 头部

头部的各字段展开如下：

![[第五届红明谷-异常行为溯源-260208-172430.png]]

```go
type header struct {
	magic_number  uint32  `魔数`
	version_major uint16  `主版本号，通常为 2`
	version_minor uint16  `次版本号，通常为 4`
	thiszone      int32   `时区`
	sigfigs       uint32  `时间戳精度`
	snaplen       uint32  `最大捕获包长度`
	network       uint32  `链路层类型`
}
```

#### 3.1.1 魔数

```go
magic_number  uint32
```

控制大小端序、后续每个帧的 `ts_usec` 是微秒还是纳秒等；并标记文件开始。

```python
0xa1b2c3d4 // 大端序，微秒
0xd4c3b2a1 // 小端序，微秒
0xa1b23c4d // 大端序，纳秒
0x4d3cb2a1 // 小端序，纳秒
```

#### 3.1.2 时区

```go
thiszone      int32
```

本地时区相对于零时区的偏移，但一般都会设为 `0`，直接用零时区。

#### 3.1.3 时间戳精度

```go
sigfigs       uint32
```

时间戳的有效数字位数，一般设为 `0` 表示所有精度。

#### 3.1.4 最大捕获长度

```go
snaplen       uint32 
```

对每个帧捕获的最大字节数，如果捕获了完整帧，则会设为 `>= 65535`；可以根据这点看 `.pcap` 中是否包含完整帧。

#### 3.1.5 链路层类型

```go
network       uint32
```

数据链路层的协议类型，一般为 `1` 表示以太网帧；

而这题为 `228` 表示 `ipv4`，这表明这个 `.pcap` 文件中的帧只会保存了网络层及以上层的信息，没有链路层和物理层信息 (无 `mac` 地址、以太网头部等信息)，通常能够反映这个包可能是在路由器上抓的。

更多类型可以看 [这个网站](https://www.tcpdump.org/linktypes.html)

### 3.2 帧

帧的各字段如下：

![[第五届红明谷-异常行为溯源-260208-193400.png]]

```go
type Frame struct {
	ts_sec   time_t  `时间戳：秒部分`
	ts_usec  uint32  `时间戳：微妙/纳秒部分(由魔数决定)`
	incl_len uint32  `捕获的包长度`
	orig_len uint32  `原始包长度`
	RawData  []byte  `帧的原始数据`
}
```

#### 3.2.1 捕获包长度与原始包长度的区别

由于头部的 `snaplen` 限制了最大的帧长度，使得 `RawData` 可能保存的不是完整帧，于是就有了两个记录长度的字段；`incl_len` 捕获帧长度代表 `RawData` 的长度，而 `orig_len` 则代表完整帧的长度。

## 4 写脚本提取 `tcp` 负载中的 `base64` 数据并解析

其实从上面的文件结构看，`base64` `payload` 本身就是可见字符，完全可以用正则匹配到 `base64` 后直接解码；

不过为了顺便练练 `.pcap` 的解析，这里我就用解析结构的方法提取出 `payload` 去解码了。

脚本如下：

```go
package main

import (
	"bufio"
	"encoding/base64"
	"encoding/json"
	"os"

	"github.com/gopacket/gopacket"
	"github.com/gopacket/gopacket/layers"
	"github.com/gopacket/gopacket/pcap"
	"github.com/samber/lo"
)

type Msg struct {
	Msg  string `json:"msg"`
	Type string `json:"type"`
}

func main() {
	f := lo.Must(os.Create("res.txt"))
	defer f.Close()
	w := bufio.NewWriter(f)

	handle := lo.Must(pcap.OpenOffline("./network_traffic.pcap"))
	defer handle.Close()

	packSrc := gopacket.NewPacketSource(handle, layers.LayerTypeIPv4)

	for pack := range packSrc.Packets() {
		if applicationLayer := pack.ApplicationLayer(); applicationLayer != nil {
			payload := applicationLayer.Payload()
			msgJson := lo.Must(base64.StdEncoding.DecodeString(string(payload)))

			var msg Msg
			lo.Must0(json.Unmarshal(msgJson, &msg))

			w.WriteString(msg.Type)
			w.WriteString(": ")
			w.Write(lo.Must(base64.StdEncoding.DecodeString(msg.Msg)))
		}
	}

	w.Flush()
}
```

最后成功提取出访问日志：

![[第五届红明谷-异常行为溯源-260208-214006.png]]

找到访问量前十的 `IP` 地址：

```bash
cat res.txt | awk '{print $2}' | sort | uniq -c | sort -r -n | head -n 10
```

其中，
1. `awk '{print $2}'` 读取每行按空格或制表分隔后的第二列，即 `ip` 地址那列
2. `sort` 按字母序排序，这主要是让相同的 `ip` 紧挨在一起
3. `uniq -c` 把紧挨在一起的重复行去重，并统计次数放在行首
4. `sort -r -n` 按数字序降序
5. `head -n 10` 只输出前 `10` 行

![[第五届红明谷-异常行为溯源-260208-214804.png]]

可以看到，`35.127.46.111` 这个 `ip` 的访问量明显高于其他的

```flag
flag{475ed6d7f74f586fb265f52eb42039b6}
```
